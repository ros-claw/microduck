# 鸭鸭抢岛：中文角色与移动目标（开发中，未验收）

这版针对 3×3 原型的两个问题：场地狭窄、决胜后所有控制器永久挤在同一位置。它使用新的 `RelayRace` 规则，不覆盖历史跳绳、跑酷或抢岛录像。

| 角色 | 标记 | 实际控制差异 |
| --- | --- | --- |
| 张三 | 紫色 | 较少避让，直接抢点；拥堵无进展时撤离重进 |
| 二呆 | 黄色 | 更看重地板损伤和拥挤程度，优先绕行 |
| 老六 | 蓝色 | 根据对手当前位置、速度预测接近方向，在目标附近尝试截路 |
| 卷王 | 珊瑚色 | 追随当前目标换点，使用中等拥挤惩罚抢位 |

名字与策略固定绑定；种子轮换出生方位，不轮换名字对应的性格。标记、文字与小地图只在渲染时加入，鸭子保留资产原有材质。策略意图不等于成功截路；是否形成有效封锁仍需从对手轨迹和接触结果判断。

## 地图与规则

25 块地板替代旧版 9 块，单格 0.40 米、间隙 8 毫米，外缘宽约 2.03 米，面积约为旧版的 3.44 倍。中央与四方外岛永久受约束支撑，连接地板根据真实脚底承重积累损伤；双鸭承重可加速开裂。释放约束后地板由重力和碰撞决定运动，不写入坠落轨迹。下方接落平台宽 6 米、顶面位于 -0.81 米，仅用于接住已经跌落的物体；可玩场地仍是上方 25 块板。

金圈是当前争夺点。只有一只未淘汰鸭位于圈内、直立且脚底实际承重时，才累计该点占领进度；积满 0.75 秒得到 1 分。对手进圈即暂停计分，即使对手短暂腾空。每次得分后，目标按公开几何顺序移往下一座岛，旧点不再计分、占领进度清零。先到 3 分获胜；超时不按名字或分数强行指定冠军。不是“最后幸存者”模式。

控制器根据当前地图、损伤与对手状态进行加权路径搜索，并用无进展检测尝试脱离拥挤。没有未来轨迹输入、位置传送、外力推鸭或预设获胜者。只复用现有 ONNX 站立、行走技能，未训练新技能，也没有在本模式中调用 Jev 或原生 ROSClaw agent。

## 运行与核验

在仓库根目录安装依赖和资产后运行（输出目录必须不存在）：

```bash
PYTHONPATH=src OPENBLAS_NUM_THREADS=1 .venv/bin/python scripts/run_relay_rumble.py \
  --seed 51003 --capture --out artifacts/relay-rumble/local-four
PYTHONPATH=src .venv/bin/python scripts/render_relay_rumble.py \
  --run artifacts/relay-rumble/local-four --out out/relay-rumble-zh.mp4
PYTHONPATH=src OPENBLAS_NUM_THREADS=1 .venv/bin/python scripts/replay_relay_rumble.py \
  --run artifacts/relay-rumble/local-four
PYTHONPATH=src OPENBLAS_NUM_THREADS=1 .venv/bin/python scripts/eval_relay_rumble.py \
  --start 52000 --count 32 --workers 3 --out artifacts/relay-rumble/local-heldout
```

仿真 4 kHz、关节控制 50 Hz；记录每步状态、控制、真实接触与公开决策。核验器重新运行整个闭环，并逐项比较状态、控制、模型、接触和决策。代码或权重变化会拒绝旧证据的核验；试跑中的源代码不得修改。

视频为同一局按时间顺序展示，包含与实际接触、落下和得分对齐的特写与慢动作。完整地图小窗帮助辨认近景位置。胜负在第三分出现时冻结，最后一秒明确标为比赛结束后的自然余势；地板不透明，跌落镜头从边缘下方展示实际身体，遮挡的角色不透过地板显示姓名。没有把不同 seed 拼成一局，也没有生成额外肢体动作。音轨为原创合成的事件提示和轻节拍，并非仿真录音。

验收数据会写在本目录 `VALIDATION.md`。统计范围仅为当前 5×5 地图、出生方位轮换及小幅关节扰动，不代表任意地图、真机或观众体验测试。头部和躯干使用保守包围盒，而非逐渲染三角形碰撞。
