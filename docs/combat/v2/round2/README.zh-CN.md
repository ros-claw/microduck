# Duck Fu V2 第二轮：持续支援与执行一致性

[English](README.md) · [首轮方法](../README.zh-CN.md) · [机器结果](../../../../artifacts/combat/v2/round2/final-evaluation.json)

这轮主要改善四鸭协作：队友受压时更早提出支援，让支援任务持续到实际接近与接触，并让画面上的角色对应正在执行的任务。运动权重、碰撞模型、电机限制与裁判保持冻结。高层仍是公开状态规则，没有新增 PPO、Jev 或在线大模型控制。

- [英文完整对局、慢动作与接触细节](media/team_review.mp4)：**86.58 秒，1080p、50 fps、静音**。前 60 秒为整场连续原速，之后明确标注 0.25× 回放及单帧定格；结果为限时平局。
- [独立连续原速参考](media/team_reference.mp4)：60 秒、720p、50 fps、静音。

本局选自冻结评估，是双方均出现合格换目标支援的展示样本，不是另一批独立测试。画面保留资产原有材质；红蓝标签区分队伍，ROOK／SHADE 为红队，BOLT／ANCHOR 为蓝队。`PEEL` 表示介入队友的追击者，`ESCAPE` 表示受保护者尝试脱离。

## 控制改动

`controller_revision: 1` 保留首轮逻辑，新增 `controller_revision: 2` 显式启用本轮改动；旧配置默认仍是 1。

1. **任务和身体同步。** 队伍计划改变后，正在承诺执行的进攻或侧闪仍保留原目标与角色，到安全动作边界才接纳新任务，并记录 `TEAM_ASSIGNMENT_ADOPTED`。之前会出现“显示 PEEL，实际仍攻击旧目标”的情况。
2. **有始有终的支援。** 以公开边缘距离、向外速度、直立程度及敌我距离估计危险。支援承诺最长保持 5 秒；安全距离、姿态与敌方远离需持续 0.8 秒才允许提前解除。人员被淘汰时立即使旧任务失效。
3. **脱离路线。** 受保护者在向内路线及两侧路线中，利用公开位置与短时速度投影避开挡路者。它只改变步行目标，身体仍由原策略和真实碰撞决定。
4. **实际入招复核。** 动态转身后准备反顶时，再检查当下支撑、姿态、角速度、关节状态和动作历史，不把较早一次安全入口沿用到整个动作链。

两种更激进的转身指令，以及基于短时净空预测的提前交接，都没有稳定改善反击，未纳入交付控制器。队友通道绕行的额外开发候选也未获独立资格验证，未合入。开发报告与源差异保留在 [round2 证据目录](../../../../artifacts/combat/v2/round2)。本轮没有新训练权重。

## 冻结后的新种子对照

执行代码冻结于 **`693f662`**，之后使用 `110001–110004` 四个新基础种子，换边、旋转朝向，比较 revision 1／2。五组共 80 局，同组同种子成对初态完全相同；40 对初态均已核验。对手、组别、版本和换边共享基础种子，不能视作 80 次独立抽样。

| 对照组 | 每个版本局数 | 数值通过，旧／新 | 合格换目标支援，旧／新 | 全场 DOWN 事件，旧／新 |
| --- | ---: | ---: | ---: | ---: |
| 主动进攻对手，15 秒单挑 | 8 | 8／8 | — | 0／0 |
| 反击对手，15 秒单挑 | 8 | 8／8 | — | 2／2 |
| 20 秒自由团战，红队 V2 对蓝队 V1 规则 | 8 | 8／8 | 1／0 | 8／6 |
| 20 秒压力初态课程 | 8 | 8／8 | 1／0 | 4／2 |
| 最长 60 秒自由团战，双方均使用 V2 | 8 | 8／8 | **2／12** | **16／21** |

长局中的合格支援覆盖 **1/8 → 7/8 局**；其中伴随保护对象近距离敌方密度下降的观测为 **0 → 8 次**。这属于保留意图、实际位移与接触的证据，不是“成功救命”或提高胜率的因果证明。长局两版本全部限时平局；新版倒地更多，短局支援也未改善，不能宣称全面优于首轮。

支援判据沿用首轮严格版本，没有为本轮修改：必须从已有目标实际切换，至少经过 0.12 秒，自身向初始新目标移动至少 3 cm，3 秒内出现冲量至少 0.01 N·s 的新接触 episode，且接触时仍保留 PEEL 角色、实际目标和相关队伍计划。同目标上的角色变化不算这项“换目标支援”。

主动进攻单挑的离线干净反击均为 4 次，反击型对手组均为 0 次。16 对单挑中 15 对控制、身体采样及阶段完全相同。**没有证明新的反击速度优势**；30% 配对延迟改善和 50% 无进展接触减少仍未达成。

## 两次展示介入

| 执行者 | 换目标／保护对象 | 换目标时间 | 新接触时间 | 向新目标实际位移 | 接触 episode 冲量 |
| --- | --- | ---: | ---: | ---: | ---: |
| ANCHOR | SHADE → ROOK；保护 BOLT | 4.22 s | 6.606375 s | 9.77 cm | 0.08586 N·s |
| SHADE | BOLT → ANCHOR；保护 ROOK | 30.98 s | 32.341875 s | 6.79 cm | 0.17667 N·s |

慢动作来自记录的积分状态，不生成插帧。定格中的黄色点和方向取自实际求解器接触日志，半透明彩色模型是碰撞几何。169.97 N、407.07 N 是选中 episode 中**单个接触的峰值法向力**；两秒定格不表示持续两秒承受该力，也不是现实机器人实测。`attack_id` 若存在，是该 episode 关联的旧响应事件，可属于接触的另一方；支援者不自动等于攻击窗口的拥有者。

## 物理与重放

80/80 局通过原数值门槛，最大穿透 **1.790 mm**；最大 3 mm、穿透样本 P99 1.5 mm 的门槛未放宽。仍为 MuJoCo 3.12.0／libccd、8 kHz、50 Hz 电机、原质量惯量、±0.6405 N·m；队友碰撞与自碰撞保留，没有根位姿运行时改写或外部击飞力。

展示局两个版本各 **480,000 步**完整闭环重放，状态最大误差为 **0**，控制历史、接触、语义日志和裁判一致；录像运行与对应非录像评估的控制／身体／阶段采样也完全相同。

两处支援附近固定输入 0.4 秒局部窗口的 dt／dt÷2 检查，分别得到最大根位置差 **0.225 mm／2.862 mm**，全鸭接触冲量相对差 **0.685%／5.223%**，两种步长均通过数值门槛。这不证明长时间闭环胜负或硬件迁移不受步长影响。

开发期间另有台缘跌落个案被严格判为数值无效：8 kHz 穿透 3.257 mm；同一局部输入改为 16 kHz 后为 4.233 mm，仍不通过。已保留证据，没有用更小步长掩盖该问题；该局未作为合格影片或新种子成功样本。见 [台缘复核](../../../../artifacts/combat/v2/round2/stage-edge-dt-check.json)。

## 复现

先按[项目安装说明](../README.md#run)准备 Python 环境和冻结资产，设置 `MICRODUCK_ROOT`、`PYTHONPATH=src`、`OPENBLAS_NUM_THREADS=1`。

```bash
python scripts/run_combat.py \
  --config configs/combat/v2/selected_team_round2.yaml \
  --seed 110001 --capture --out artifacts/combat/local/round2-reproduction

python scripts/eval_combat_revision_v2.py \
  --out artifacts/combat/local/round2-new-evaluation \
  --group pressure --group counter --group free --group course --group open \
  --revision 1 --revision 2 --seed-base 110001 --seeds 4 --jobs 6 --split validation
```

完整状态／原始接触大文件保留在本地；仓库提供源配置、压缩原始汇总、文件散列、逐帧映射和校验结果。重建路径及环境差异可能改变 manifest 散列；闭环精确重放需使用与记录一致的执行源、MuJoCo 版本和冻结资产。本轮 **215 项测试通过**。

后续重点仍是从真实前序技能状态训练更快的侧闪后转身、降低长局倒地和安全完成支援后的重组。当前是开发版本；视觉验收、官方 ROSClaw 授权回执和真机验证尚未完成，未创建 Release 或 tag。
