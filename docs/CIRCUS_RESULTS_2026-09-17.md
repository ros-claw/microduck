# 四鸭马戏团：第一轮实现与实测（2026-09-17）

**当前状态：已实现可运行的第一阶段原型与验收流程；四鸭完整接力、无碰撞入绳和加速 30% 均未通过，不能作为成功演示发布。**

原始需求来自 `~/workspace/tennis/更酷的demo尝试.md`。按优先级先推进四鸭接力和加速挑战；双摇、移动跳绳、跷跷板、助跳、搬运与自由编排仍是后续阶段。TennisForge 仓库未修改。

## 已实现的部分

- 四只真实机器人在同一 MuJoCo 世界中运行；Graphite 与绳、地面和其他机器人保留接触。绳两端继续由转绳鸭的嘴部把手驱动。
- 扩展原有评估器，分别审计 Sky 与 Graphite；增加双跳者碰撞、同一圈共同通过、实际入绳和退出边界检查。
- 将 `5 圈独跳 → 入绳 → 3 圈双跳 → 退场 → 5 圈独跳 → 谢幕` 实现为事件驱动状态机。失败圈重置连续计数，不能用定时器推进。
- 支持有界的中英文任务解析，计划中的圈数可以直接传给排练器。该解析器不是任意自然语言 LLM 编排器。
- 实现参数 Practice、独立种子验证、Darwin 晋级和证据日志。任务种类、协议、种子划分或证据不满足要求时拒绝晋级。
- 实现逐级加速试验，检查实际转绳频率；失败后停止升档。较低档位通过不会被记为“加速 30% 成功”。
- 增加跳跃策略的目标位置接口，只生成既有速度命令；不移动自由关节、不瞬移机器人。它用于验证现成技能能否组合成移动跳跃。

当前 Practice 后端是**真实物理试验中的控制参数搜索**，没有自动重训 PPO。本轮没有发布新的神经策略，也没有声称已经学会无碰撞入绳。

## 这轮查出的关键问题

1. **绳圈空间不是三鸭场景的简单扩展。** 原圈偏窄，扩大后绳长、反作用力、起旋和跳跃者站位共同变化。
2. **绳外等待区必须按整个碰撞几何判断。** 原先只按根位置与固定距离判断，扩大绳圈后会把实际可能被扫到的站位误称为“绳外”。当前使用绳长形成的保守扫掠包络，并检查整个机器人碰撞几何。
3. **入绳相位不能只用绳外机器人的局部位置。** 它可能一直看不到目标相位而不启动。启动门控改用绳内参考相位，并测试局部与前方跳跃者相位反馈。
4. **单独通过率不能替代双跳共同通过率。** 即使两只鸭各自达到 80%，若失败圈错开，共同成功率可能只有 60%。已加入对应反例测试。
5. **阶段缺失应如实停留在未通过状态。** 本轮没有补写文档中的 38%→71%→93% 示例成绩，也没有将训练奖励或后半段恢复片段算作完整接力成功。

## 接下来应训练什么

先针对安全等待区到绳内目标点的**移动跳跃与落地减速**建立训练课程，再加入第二跳跃者的接触与占位约束。入口策略需要在未见过的相位、位置和绳速上独立验证；仅有单次成功才可以继续尝试完整接力，不能直接晋级。

之后验证无碰撞退场和稳定谢幕。双摇必须另行审计单次腾空内两次完整脚下穿越；跷跷板需要独立的接触力矩与平衡评估。当前代码没有把这些后续能力标记为 READY。
