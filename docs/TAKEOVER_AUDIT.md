# 接手审计：原版 93% 不代表真实跳绳成功

日期：2026-09-10。交付仓库起点 `a14180c`，本次代码与实验保存在本地工作区。

本轮已复现原版、恢复可配置的绳地/绳鸭碰撞、增加逐物理步诊断，并撤回 README
中“无跌倒、122 次干净跳过”的描述。**尚未达到真实跳绳 80% 的验收目标。**
未训练新策略，原交付视频和策略权重保持原样。

## 已核实的问题

1. 原始程序确实报告 `122/131`，但统计的是绳腹低于阈值的时间窗口中，脚部 site
   是否腾空、躯干倾角是否小于 60°。没有绳脚接触，也没有检查落地或实际过脚路径。
   因此这些计数不能命名为 clean skips；本轮将录制脚本字幕改为 TIMING。
2. 原版的 51 秒物理过程（1 秒预热 + 50 秒演示）有 **17.960 秒**存在跳跃鸭非脚部
   与地面的有效接触。跳跃模式期间 **30.7%** 的物理步躯干倾斜超过 45°。
   非脚部触地时长不是跌倒次数，45° 也是诊断阈值；但它们足以否定“无跌倒”的保证。
   对原视频 0、8、15、25、35、45 秒抽帧，15 秒等画面也能看到明显前扑。
3. 原版 connect 的两个实际约束锚点之间，50 Hz 采样的最大距离 **75.9 mm**。
   存在 connect 不等于绳端始终紧贴嘴。这个误差还没有计入绳起始段相对 wrapper
   的可视偏移：`seg_0` 的 body 原点沿 x 偏移一个节长，近端约束却连在 wrapper 原点。
4. 原版绳胶囊表面的最低采样高度为 **-37.6 mm**，与无地面碰撞的设置一致。
5. 开启真实接触后，四颗测试种子均完成 51,000 个物理步，没有 MuJoCo warning、
   非有限状态或时间重置。交接中“接触会炸”的历史记录不等于当前配置必然崩溃。
   **这四次通过只证明本次测试中的数值稳定性，不代表鲁棒性或动作成功。**

## 实验对照

共同设置：MuJoCo 3.12.0、CG/100 iterations、1 ms 物理步长、50 Hz 策略、原始
两份 ONNX、三铰链绳、嘴部 handles 连接、24 段、L=0.50 m、density=500。
所有碰撞从初始化起启用，不在起旋或跳跃时临时切换。保留旧版每步绳速钳制 ±40；
并未证明无此数值干预时能稳定运行。转绳鸭与绳的排除对、绳自身无碰撞也仍然存在。

| 模式 / seed | 旧时序命中/窗口 | 绳鸭接触秒 | 绳地接触秒 | 非脚部触地秒 | 跳跃时倾斜>45° | 最大锚点间距 mm |
|---|---:|---:|---:|---:|---:|---:|
| off / 0 | 122/131 | 0 | 0 | 17.960 | 30.7% | 75.9 |
| floor / 0 | 127/131 | 0 | 3.900 | 17.964 | 30.2% | 63.5 |
| jumper / 0 | 30/47 | 5.552 | 0 | 17.681 | 34.0% | 171.4 |
| full / 0 | 7/16 | 12.540 | 28.903 | 17.322 | 38.7% | 124.9 |
| full / 1 | 121/132 | 0.539 | 3.911 | 18.115 | 32.5% | 82.9 |
| full / 2 | 8/18 | 3.865 | 34.339 | 17.629 | 33.8% | 129.7 |
| full / 3 | 13/22 | 0.591 | 4.347 | 17.947 | 31.7% | 153.5 |

时长按有该类有效接触的物理步数 × 0.001 计算，同一步多个接触只计一次，包含预热。
只统计 `efc_address >= 0` 的接触，不把仅进入候选范围的接近当碰撞。接触秒数不等于
碰撞冲量，也不等于绊倒次数。锚点误差和绳最低表面高度为 50 Hz 采样，不能排除采样
间隙中的更大瞬时值。旧时序命中列只是复现证据，**表内没有任何物理成功率**。

启用地面接触并不意味着完全无穿透：full 四组的最低表面采样值仍约 -16 至 -19 mm，
远大于 3 mm 绳半径。当前软接触参数还不能通过几何质量验收。

## 复现与验证

在交付仓库根目录运行（沿用现有本地 robot / 基础策略路径）：

```bash
.venv/bin/python scripts/audit_honest_skip.py --contacts off --seed 0 --output artifacts/baseline.json
.venv/bin/python scripts/audit_honest_skip.py --contacts full --seed 0 --output artifacts/full.json
.venv/bin/python scripts/audit_honest_skip.py --contacts full --seed 1 --output artifacts/full-1.json
uv run --with pytest python -m pytest tests/test_rope_contacts.py -q
```

`floor` 和 `jumper` 用于独立对照；`--solver Newton` 可用于后续求解器实验，本轮
未测试 Newton。无渲染不创建 GL 上下文，不需要 OSMesa。任何 warning、非有限状态
或仿真时间自动重置都会写出失败结果，并以非零状态退出。

本轮五项回归测试通过：四种模式分别检查绳地、绳脚路由，脚地接触、视觉网格不参与
碰撞、无 mocap、编译后的 body broadphase 掩码；非法模式与暂不支持的绳类型明确报错。
默认原版 demo 的动力学保持不变，所以仍可与交付视频对照。

## 接下来必须通过的关卡

1. **先修单鸭跳跃质量。** 独立验证跳跃策略在同一 CPU/执行器设置下的腾空、
   非脚部触地、躯干姿态和落地；查清训练奖励漏洞与部署差异。原版碰撞关闭时已经
   出现大量非脚部触地，所以不能把所有翻倒归因于绳。
2. **修绳端几何与约束。** 消除 wrapper 到第一可视段的一节偏移，实测收紧 connect
   后的锚点误差、转绳鸭平衡与起旋，避免只在 XML 中“写了连接”就算达标。
3. **接触与计分一起验收。** 连续追踪同一绳段的过顶/过脚运动；检查绳横跨双脚
   实际位置、脚底净空、全周期绳鸭接触和后续直立落地。绳在旁边扫、翻倒抬脚、
   周期不完整、绳停转都不能算成功。软接触穿透也必须纳入质量阈值。
4. **最后做鲁棒性与视频。** 预先固定训练外种子和运行时长，所有失败起旋都记入
   episode 通过率；同时报告逐圈清洁通过率。两者分开报告，避免只对成功起旋的
   部分片段统计 80%。达到这些条件后再调整镜头与甩头动作的可读性。

以上是后续实现与验证要求，尚未宣称完成。当前可交付的是可靠的诊断基线与真实接触
实验入口，不是已经修好的跳绳表演。
